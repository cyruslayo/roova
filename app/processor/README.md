# Node/FFmpeg media processor

Node 22+ and FFmpeg/FFprobe on PATH. Run `npm install && npm test`. `node dist/cli.js --input ./clip.mp4 --out ./run` performs a dry-run validate/prepare; generation is impossible unless `--submit --confirm-paid` are both given. `--worker` runs the authenticated internal API loop. Configure `WORKER_API_URL`, `WORKER_API_TOKEN`, `WLT_API_KEY`; optionally `PROCESSOR_WORKDIR`, `FFMPEG_PATH`, and `FFPROBE_PATH`.

Validation decodes the complete clip, checks supported container+video codec and rejects duration >30 seconds. No selection, trimming, speed change or segment logic exists. Files over 100,000,000 bytes get whole-clip H.264 MP4 transcode attempts targeting 95,000,000 bytes; duration is rechecked. If unable to fit, fail with redelivery guidance. Source is retained.

Paid requests use private Marble `marble-1.1`. Per-job `state.json` is persisted as `start_uncertain` before generate POST. An ambiguous POST is never retried. A known `operationId` is resumed with GET polling and asset collection after processor restart; transient poll failures retry. Provider output is downloaded privately (poster, panorama, available 100k/500k SPZ), spatial values and settled credits (`total_credits`) are recorded. Asset formats are derived from provider URLs. Missing optional assets are omitted; review is required. Upload MIME matches the source extension; oversized media is transcoded to MP4.

## Internal Worker API contract expected

The backend must authenticate the processor with bearer `WORKER_API_TOKEN` (TLS required outside localhost), return `POST /api/internal/jobs/claim` as `{job:{id,tourId,uploadKey,sourceBytes,title}}` or `{job:null}`, and atomically lease claims. `GET /api/internal/media/:key` streams source bytes. `POST /api/internal/jobs/:id/events` accepts `{phase,...}`. `POST /api/internal/jobs/:id/assets?name=...` accepts raw asset bytes and exact `Content-Type`; backend stores them privately and returns `{key,bytes}`. The processor posts `collecting` before staging assets, then `ready_for_review` with numeric `cost`, `durationSeconds`, decimal `providerBytes` (plus `bytes` compatibility alias), `worldId`, `spatial`, and assets `{name,file,key,bytes,contentType}`. The backend's current route snapshot only whitelists `poster.webp` and `panorama.jpg`; it must be widened to preserve provider PNG formats (`poster.png`, `panorama.png`) with `image/png`. Persist `start_uncertain` durably before accepting later worker events; the processor additionally writes local state. Keep internal routes inaccessible to browsers and public traffic.

Standalone mode reads `--input`, writes transcodes/state/provider outputs to `--out`, and does not invoke provider APIs unless explicit paid flags are used. The parent project reports a successful private live generation in `README-FIRST.md` and `docs/07-CURRENT-STATUS-AND-ACCEPTANCE.md`: 29.7-second input, operation `be5caa97-8b03-4652-85ea-7425263a40b2`, world `1bc10832-cefc-4206-b4b5-7464aadaae16`, and 1,600 credits charged. The earlier 16s, 105.5MB-to-7.6MB result is local preparation evidence, not that live operation.
